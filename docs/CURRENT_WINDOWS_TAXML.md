# Current Windows TaxML inspection and corrected XML copies

This is independently written local code informed by source-bound REA observations of the Windows2025 XML writer. It accepts explicitly declared plaintext XML or a single-document plaintext ZIP, an explicit JSON profile, and the caller's own XPRF registry bytes. It validates the actual carrier hash, resource identity, kind/format metadata, root/entity/formset/form namespaces and six W-2 money fields. Internal XPRF formset identity and the XML formset name are explicitly bound separately; they are not assumed to be the same.

Current cent fields contain dollar decimals on the wire. The original copyNum0 is valid for this current profile. Older caller-defined profiles keep their existing copy rules. Unknown siblings or fields, duplicate copies, incompatible kinds, aliases, arrays, unknown flags, true nondefault flags and unused values block review/export. Explicit used=true zero is retained. Empty/missing Boxes7/10 are not silently converted to zero. Employer and owner require review; source attributes do not establish who owns the W-2.

Use Documents → Inspect TaxML / plaintext.tax. Choose the source, declare its format, choose the matching profile and XPRF, and acknowledge the profile. For a reproducible synthetic example, select the three `synthetic-modern-windows-*` XML/profile/XPRF files under fixtures/taxml. OwnedSet, OWNED, checksum1 and implementationVersion owned are unregistered synthetic example values. The XPRF file is real independently authored registry structure; a metadata JSON and matching claimed hash cannot substitute for it.

Review the six amounts, enter employer/owner, and explicitly establish Boxes7/10. Add reviewed W-2 appends a normal draft record that participates in federal calculations, save/reopen and source review metadata. It never marks all income reported. Download corrected XML creates a separate plaintext XML copy with exactly six supported amount-text destinations available for edits. It does not edit owner/employer/Boxes7/10 in the source. A lexical byte editor replaces only bound leaf-text spans, then reparses and re-inspects the result. It retains the original attachment and every byte outside the edited spans, including namespaces and outer comments. A plaintext ZIP source is retained as a ZIP; the corrected output is XML rather than a rebuilt container.

Actual browser acceptance passed in HTTP/SQLite and actual pinned Pyodide/IndexedDB modes. The HTTP example changed wages1234.56→1234.57 and withholding123→124.00, produced refund124, saved/reopened the reviewed W-2, downloaded corrected XML and downloaded the unchanged original attachment. The offline example changed wages→1234.58 and withholding→125.00, produced refund125, saved/reopened IndexedDB and read back the saved JSON and original attachment. Only the two changed value-text spans differed in both output XML files. See qa/taxml/current-windows-browser-acceptance.json and current-windows-offline-browser-acceptance.json.

Host tests540 pass; real Pyodide470 executed tests pass with one host-only skip. Integrated worker tests also exercise new native-shaped import, registry validation, corrected output, invalid amounts, an unknown sibling, stale cloned candidate rejection and reviewed federal calculation.

This is not complete.tax compatibility, a original-engine writer or original return recalculation. It does not rewrite native template checksums, rebuild protected TaxContainer files or establish original-program loading. Original native executions and validated original saved-return fixtures remain0. Full-return XML containing other unsupported tax facts stays blocked. Native installation, changed-flow UI acceptance and publication of preview13 packages are recorded separately.
