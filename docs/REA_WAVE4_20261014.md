## Actual paths recovered

The original field-change path deduplicates changes, expands reader dependencies and constructs execution queues. An apparently empty queue can still add external-value work. A completion counter alone is not a saving barrier.

Typed inputs are cached by XPath. The data-source path creates a typed blank when a source cannot be read or written or an instance has no value. Numeric blank and explicit zero are separate states. Default getter filtering resolves the previous isolated `HasValue` question: a pointer-backed false object in an opcode probe does not automatically survive the default field-attribute filter.

Results enter an output cache before final TPS writing. Actual chained-fixup slots and function bodies show that temporary nodes, error nodes and values marked `IsUserInput` are skipped by ordinary calculated-output writing. A later setter also protects an existing field attribute; its complete UI meaning remains open. The independent application preserves entered data separately from calculation results, but this is not a claim that the entire original scheduler has been reproduced.

The local field-value format has an 11-byte ordinary representation and a 6-byte compact representation. Those observations do not establish the surrounding `.tax` version/container selection.

The legacy encrypted-file chain reaches the actual Blowfish key schedule, block primitive and CBC implementation. An independently written private mechanism passes 24 synthetic ASCII-key/length comparisons with an independent library, including decrypt roundtrip and IV updates. File headers, credential/key derivation, original payload-length/padding conventions, version dispatch and original-file roundtrip remain unresolved. This compatibility investigation does not select legacy encryption for new application data.

## Original behavior now used in the App

The scoped absolute investment-basis replacement is implemented with stable target identity, local history, recalculation and save/reopen/backup checks. Those product checks are documented in [investment corrections](INVESTMENT_BASIS_CORRECTIONS.md).

The original printing code supplies a second concrete contract: `maskField`, the default replacement chain, and the builder that replaces the field value. The original catch is specifically `FmtInputException`; a regex syntax failure is converted into that exception. It writes a null masked string and preserves taint. Other exceptions are not claimed to be swallowed. Our independent [masked Form 1040 review export](MASKED_REVIEW_COPY.md) uses an explicit field whitelist, a fresh blank IRS template, and refusal on any selected-identifier leak. Its broader refusal policy is our own choice.

Interest/dividend review snapshots are per instance, and review is separate from completeness. A successful original import replaces an explicitly identified old placeholder and clears transient context. Those flows have not yet been installed into the current App.

The original 1099-NEC/K paths carry form UUID and business/rental source. Hard-stop state and the previously-visited flag have distinct behavior; clearing the flag occurs before navigation once that stop is resolved. Gross-payment string comparisons are not formulas. These contracts still need an independent source-to-business/rental association and usable review workflow.

The printing caller clarifies that EXCLUDE applies to additional-form selection independently from main forms. Watermark/annotation drawing returns a boolean that actual callers discard. Non-scaling text truncation records count and field identity, and an empty complete PDF is rejected. Exact fonts, layout, whole-assembly semantics and original pixel matching remain open.
