# REA wave 7: source-bound import and calculation work

This checkpoint separates original binary evidence, independent implementations,
executed App workflows and unresolved compatibility. It does not establish full
TurboTax recovery or original application execution.

## Calculation evidence

REA read source-bound native windows for field assignment, calculated-value
assignment, indexing and form opening. A private, independently authored
interpreter then completed the selected original compiled-resource paths:

- The full ordinary federal-tax caller and its year, table-bucket and tax
  functions matched 12,472 independent comparisons extracted from the primary
  [2025 IRS Form 1040 instructions](https://www.irs.gov/pub/irs-pdf/i1040gi.pdf).
  Three additional cases verified the source year representations 25 and 2025.
- The independently written App's ordinary-tax function matched the same 12,472
  cases. This covers ordinary income and all five filing statuses with the
  selected foreign-income offset set to zero. It does not cover preferential
  gains, AMT, credits or complete calculation scheduling.
- Six finite W-2 cases completed the selected original raw W-2 summary, payment
  worksheet and 1040 withholding/total-payment sections. No calculated bridge
  totals were supplied. The context used empty optional arrays and an existing
  registered savings-credit form. New-form creation, interrupt callbacks and
  full runtime scheduling remain unresolved.

Original TurboTax executable executions in these checks: **zero**. The private
interpreter's results are static reconstruction evidence. They are not results
obtained by opening an original return in TurboTax.

The selected internal W-2 path rounds individual statement amounts to whole
dollars. Some synthetic cents cases therefore differ from the App's aggregate
rounding. The IRS instructions say to include cents when adding amounts for a
line and round the total. The App retains that IRS-based policy. The original
loader/value-conversion/runtime context must be reconciled before claiming a
product-level discrepancy or changing the App.

## File-format evidence

The source-bound native dictionary path distinguishes visible and hidden field
resources. Its rows have a 33-byte field ID, a one-byte kind, a one-byte format
and a four-byte attributes value. The shipped federal carriers contain 863
template entries, 848 distinct form IDs and 124,937 field rows. Fifteen repeated
form IDs have different dictionaries, so an exact carrier/resource identity is
required. These are structural counts, not implemented feature counts.

Native resource captions corrected a material W-2 binding: `CA` and continuation
`CA2` represent the employer name; `NAME` is a separate form-level field.
`SSTIPS` and `DCB` correspond to Boxes 7 and 10. Amount values keep their cents;
an empty amount does not prove zero. Statement ownership is reviewed explicitly.

The independently written codec reads actual XML and ZIP bytes and caller-owned
XPRF metadata. It preserves unchanged input bytes, reads the supported scalar
subset and can serialize selected known-value edits while preserving supported
opaque structures. Ambiguous templates, unknown namespace/header semantics,
unsupported array/persistent-object data and unsafe namespace rewrites are
rejected. It includes no vendor registry, compiled program, encryption key or
activation bypass.

The file codec passed 25 synthetic test methods. A separate worker ran 37
independent malformed-input, ambiguity and preservation probes. The registry
loader was also checked against the private original structural inventory.
These are not original saved-return roundtrip tests.

## App integration boundary

The App adapter offers reviewed W-2 candidates from explicitly bound plaintext
TaxML or declared plaintext ZIP. The user supplies the document, its wire profile
and the matching local registry files. It appends reviewed W-2 records and retains
source hashes, carrier/resource identity and review receipts through persistence
and backup. Missing boxes stay blank until explicitly reviewed; unresolved facts
block adding a record. The adapter does not replace a whole return, assert that
all income has been reported, decrypt a file or write an original `.tax` return.

Version-specific implementation, browser and package receipts determine whether
this adapter is present and tested in a particular download. Preview.6 predates
the adapter. Its page/copy export completeness checks are already included.

## Work still open

The remaining work includes encrypted manifest/document context and integrity,
actual original saved-return fixtures, runtime root/template dispatch, array
capacity and scalar grammars, persistent objects, setter/default/override state,
form creation and calculation invalidation/queue behavior. Standard/itemized
deductions, preferential gains and complete liability branches are being traced.
Full original `.tax` compatibility, original result parity and e-filing are not
established. None of these gaps is classified as impossible simply because this
checkpoint has not closed it.

Private original binaries, resources, code windows and decompiler bodies are not
distributed. Public code and documentation are independently authored.
