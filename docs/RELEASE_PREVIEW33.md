# Preview33 — date source corrections and complete stored-map preservation

The main App now inspects and corrects existing date, month/day and year/month source fields. The explicit v3 profile binds each field to its complete registry, entity and stored copy. Export writes a separate complete XML or cleartext ZIP, then reads it back and checks every other field and local record. Dates stay separate from income, household facts and the current IRS return.

Complete supported binary sources can also retain nonempty saved FormSet instance-address maps while an existing numeric field is corrected. Both compressed frame kinds are checked. The independently generated example contains two FormSets, eight forms, nonempty tables, child forms, eight links and six saved address pairs. Its complete corrected file is 8,360 bytes. The stored map remains a preserved source object; native cache cleanup, migration and current UUID inventory have not run. Unknown versions and ambiguous empty compressed bodies remain opaque and cannot be moved.

Date, decimal and binary source dialogs now discard late Worker results after an input change, a different selection, revoked confirmation or closing the dialog. Independent actual-browser review covered 24 interrupted exports and ten ordinary complete downloads. The current return stayed unchanged.
