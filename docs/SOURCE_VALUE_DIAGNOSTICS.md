# Read-only source relationship and interest checks

These two Documents tools inspect a supported complete binary source. They do not change the source or the current IRS return. Their reports describe saved source facts and independently constructed input values, rather than an active TurboTax session.

## Saved links

Open a complete source with its explicit automatic-table profile and ordered registry files, then choose **Check stored links**. The check joins each saved D7 relationship with its full D2 field identity, reachable kind22 value, source FormSet, stored copy identity, and matching 2150 definition. It reports unresolved relationships separately. **Download read-only check** saves the result; it does not grant link editing permission or certify the whole return.

Documents also includes **Load saved-link check sample**. Its complete 713-byte source and 848-byte registry are independently authored test data. They contain one receiving field and one saved relationship, with deliberately different saved and current field ordinals. The independent audit verifier reopens those complete bytes without calling the diagnostic API.

## One stored interest input

After inspecting a supported v5 interest source, choose **Read stored source interest input**. Select the two matching local `.3pe` files requested by the tool, then confirm the read-only scope. Files are identified by their complete content hashes, rather than their filenames. The application does not ship, download, or upload those original resource files. The ordinary IRS return-preparation workflows do not require them.

The current finite profile reads one already-existing Used1 kind11 field: F1099I L1, L3, or EXINT. It derives the source field binding, signed cents, recorded status, saved FormUUID149, source namespace, instance vector, MC map, error reduction, and repeated owned-cache result from the complete request. A source zero that is explicitly present stays present. Missing or Unused values, unknown UUIDs, unsupported owners, reordered resources, and supplied cache/amount/ready flags are refused. The masks1/3/9/11 and absolute one-billion-USD bound are chosen implementation limits, not claimed original-product limits.

The report labels its completed scope as an owned selected-current-input projection. It does not restore an active native cache, associate a native RecordUUID, execute the complete native GetMultiCopyInputValue, calculate final tax, or update the source. The application keeps the selected source, resource order and current return bound across file reading, calculation and saving; changing or closing them discards stale results. Saving a report uses the existing browser or native system-save path.

## Verification boundaries

The source tools and full source-file readback have separate host, actual Pyodide, browser storage, and native-package checks. Controlled save adapters are not OS Save evidence. Installed-runtime kernel fixtures use independently authored amounts and do not establish original-resource positive acceptance. Platform-specific receipts identify which flows were actually executed.

Complete original encrypted `.tax` compatibility, native Load/observer inventory, the complete original recalculation engine and real original saved-return parity remain unverified. No activation or license bypass is included.
